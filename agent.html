For coding agents

Your agent drafts it. You finish it.

A coding agent — Claude Code, Cursor, Codex — takes the screenshot, drafts the arrow and the one-liner, and opens that draft in FletchShot. You fix the positions and the wording, then press ⌘↩. The finished image goes back to the agent, which carries it the rest of the way: into a README, a PR, a bug report.

The bridge is a free MCP server, fletchshot-mcp. There is nothing to configure inside FletchShot.

What happens

1The agent captures and drafts

Ask it to “put an arrow and a note on this part of the screen”, or just approve what it proposes. Which window to capture, where the arrow points, what the label says — the agent decides all of it.

2You fix it, then ⌘↩

A draft note opens. Arrows, text and mosaics are all grabbable, exactly as usual. When it looks right, hit Return (⌘↩) and the note closes.

3The agent picks it up and moves on

It receives the flattened image — and pastes it into the README, attaches it to the PR, adds it to the issue. That part is the agent's job again.

Why put FletchShot in the middle

There are other MCP servers that annotate a screenshot and hand it back. Most of them return pixels with the annotation burned in. When the agent gets it right, that is perfectly fine. It is the near-misses that hurt: the arrowhead lands a few dozen pixels off and covers the very word it points at, the label overlaps a line of body text. Once it is burned into the pixels, you cannot nudge it. Your choices are to re-prompt and hope, or to let it go.

FletchShot opens the draft as annotations you can grab. A misplaced arrow gets dragged where it belongs. Wrong wording gets retyped. Something you would rather not show gets a mosaic you add yourself. Fixing beats re-prompting more often than you would guess.

If you only need the agent to look at your screen, skip this

To simply show an agent what is on screen, screencapture — already in macOS — is enough: -l for a single window, -R for a region. FletchShot earns its place when the image is headed for a person: whoever reads the README, reviews the PR, or opens your support reply.

The image reaches the agent only when you press Return, or when a draft is burned quietly

FletchShot does not use the network. An image goes to the agent only when you press Return (⌘↩) inside a draft note, or when the agent marked the draft to be burned quietly.

  • Burning quietly (FletchShot 2.5.0 or later) is for light annotations that need no touch-up. Ask the agent to “burn it in quietly” and FletchShot burns in the annotations without opening a note and returns the image to the same file. It goes back before you see it, so don't use it for anything you want to check first. FletchShot has no setting that makes this the default.
  • You can reopen a quietly burned image from the Agent-Burned Images menu and fix it. The copies kept for that (the image before burning and its annotations) stay inside FletchShot and are never given to the agent.
  • Copy (⌘C), save, drag, share and Send to Shortcuts do not return anything. Handing an image to someone else is not read as consent to hand it to an agent.
  • Only the finished image, with mosaics burned in, is returned. The unannotated original never is.
  • The Return button appears only in notes opened from an agent's draft. Your usual ⌥⌘4 notes look exactly the same as they always did.
  • fletchshot-mcp speaks stdio only and uses no network at all. It does not watch your screen, and it does not read FletchShot's documents on its own.

What happens to the image after you return it depends on your agent's own settings — if it sends images to its AI backend, that is where this one goes too. Which is the whole point of looking at it before you return it. Burn quietly only when you know you don't need to look.

Setup

Install FletchShot from the Mac App Store, then register the MCP server with your agent.

claude mcp add fletchshot -- npx -y fletchshot-mcp

Cursor and Codex CLI config, the permission you need (Screen Recording), and the details are in the help page.

Help: Working with a coding agent →

What you need

  • macOS 14 or later, and FletchShot (Mac App Store build)
  • Node.js 18 or later (to run the MCP server via npx)
  • Screen Recording permission for the terminal or editor running your agent (System Settings › Privacy & Security › Screen Recording). Capturing a single window also uses the Xcode Command Line Tools

What this deliberately doesn't do

This path is scoped to one thing: an agent's draft, finished by a human, handed back. The following are left out on purpose.

  • Any route that returns an image without a human acting — auto-return, “it's ready” notifications, reusing copy or save as a hand-off.
  • Letting the agent drive your screen — screen watching, UI automation, agents looking at the result and silently redrawing in a loop.
  • Settings inside FletchShot. There is no preference pane for this. Setup conventions change on the agent's side, so they live in the help page, where they can be fixed without shipping an app update.
